# release an artifact into a community loop

Use this when a team, community, course, or practice group releases a template, script, guide, prompt, dataset, or small tool and wants it to create durable value instead of a one-time content spike.

## inputs

- Artifact or template ready for controlled release.
- Stated use case and audience.
- Place to record requests, feedback, outcomes, and versions.
- Named reviewer or operator role for triage.

## steps

1. **State the layer.** Name whether the artifact is a commodity baseline, a reusable internal tool, a lead magnet, or a governed operating asset.
2. **Define the use case.** Say what real job it helps with, who should use it, what inputs it expects, and what it cannot do.
3. **Publish with intake.** Release the artifact together with a short request/feedback form: problem, current cost, desired output, constraints, and permission to reuse lessons.
4. **Route requests.** Triage each response into: self-serve usage, artifact defect, paid/high-value request, operator handoff, or not a fit.
5. **Record proof.** For each routed item, log shipped output, review handle, user outcome, rejected scope, and follow-up.
6. **Improve by repetition.** Update the artifact only when multiple uses show the same gap or one high-consequence use exposes a clear defect.
7. **Move up the layer.** If the artifact becomes easy for users to produce themselves, treat it as proof-of-work and charge or govern the discovery, integration, review, coordination, or accountability layer above it.

## verification

The loop is working when released artifacts produce visible use cases, improvements, routed opportunities, and outcome evidence. It is not working if the only metric is downloads, likes, or chat applause.
