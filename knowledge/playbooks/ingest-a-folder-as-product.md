# ingest a folder as a product

Use this when a folder, zip, export, repo, or knowledge pack is supposed to
become useful to an agent or team.

## steps

1. Copy the source into a working area. Do not mutate the original.
2. Create a front desk file that explains purpose, status, and entry points.
3. Build a manifest of files and folders.
4. Mark canonical inputs, mutable work files, generated outputs, and private
   source material.
5. Write a theme index for concepts and topics.
6. Write a problem index for repeated failures and fixes.
7. Add request slips for common jobs.
8. Add a tool registry if scripts or APIs exist.
9. Run a fresh-session onboarding test: ask what is here and where to start.
10. Record gaps before adding agents.

## acceptance test

A fresh authorized operator can enter the folder, identify the canonical source,
run one bounded task, verify the result, and export an artifact without reading a
previous chat transcript.
