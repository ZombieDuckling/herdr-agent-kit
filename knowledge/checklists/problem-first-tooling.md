# problem-first tooling checklist

Use this gate before approving a new tool-learning path, outsourced task,
automation build, or agent workflow.

## problem proof

- [ ] The buyer, user, or accountable operator is named by role.
- [ ] The blocked outcome is stated without tool jargon.
- [ ] The current manual path is known, even if it is slow.
- [ ] The bottleneck is classified: judgment, taste, data, repetition, transfer,
      source navigation, review load, permission boundary, or capacity.
- [ ] The first accepted result is defined and reviewable.

## value and opportunity cost

- [ ] The scarce human hour is named by role.
- [ ] The work that scarce hour should be saved for is stated.
- [ ] Delegated or automated prep work has a clear handoff and review surface.
- [ ] The expected time saved, quality gain, or risk reduction exceeds the
      mechanism's setup, review, and failure cost.
- [ ] Doing nothing or waiting for a clearer demand has been considered.

## mechanism fit

- [ ] A checklist or markdown workflow was considered before tool training.
- [ ] A template or deterministic script was considered before model calls.
- [ ] Delegation was considered where another person can safely buy back scarce
      attention.
- [ ] One model call was considered before an agent loop.
- [ ] A full integration is justified by repeated volume, stability, governance,
      or sharing needs.
- [ ] Rejected mechanisms are recorded with concrete reasons.

## human judgment protection

- [ ] Taste, strategy, authority, and high-consequence decisions stay with an
      accountable human or review gate.
- [ ] The workflow can pause when missing context becomes visible.
- [ ] The review surface shows whether the valued bottleneck moved.

## acceptance

- [ ] The first real case produced an accepted output.
- [ ] The accepted output moved the valuable problem, not merely the tool skill.
- [ ] The next escalation trigger is written before further investment.
