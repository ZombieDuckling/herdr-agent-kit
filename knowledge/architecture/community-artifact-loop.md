# community artifact loop

A community or internal practice group does not become valuable because it drops files into chat. It becomes valuable when artifacts create use, use creates feedback, feedback creates better artifacts, and the loop routes real work to capable operators.

## components

| component | purpose | minimum contents |
|---|---|---|
| Artifact catalog | Makes reusable assets findable | title, version, status, use case, owner role, license/access class, source link |
| Use-case intake | Turns attention into work | requester role, problem, current cost, desired output, deadline, constraints |
| Capability board | Shows who can fulfill what | operator role, skills, capacity, proof artifacts, unavailable work |
| Feedback queue | Converts use into improvements | artifact id, user problem, failure/success, requested change, priority |
| Deal-flow board | Routes paid or high-value opportunities | request, value class, fulfillment path, claimed by, status, outcome |
| Proof ledger | Prevents value from vanishing into chat | shipped artifact, user outcome, evidence pointer, lesson, next action |
| Governance notes | Keeps incentives and access explicit | contribution rules, review rights, compensation/upside model, privacy limits |

## flow

1. Release a reusable artifact with a clear use case and version.
2. Ask users to apply it to real problems, not merely react to the announcement.
3. Capture each use case as an intake item with cost, constraints, and desired outcome.
4. Route repeatable or valuable requests to an operator, automation, or backlog.
5. Record outcome evidence: shipped work, rejected request, defect, testimonial, or follow-up need.
6. Update the artifact or split a new artifact only when repeated use proves the need.
7. Promote the loop's proof, not the raw download count.

## failure modes

- The community has content drops but no request board.
- Feedback stays in chat and never changes the artifact.
- Operators claim work without capacity, review, or proof requirements.
- The same artifact is regenerated repeatedly instead of versioned and improved.
- Incentives are implied, so contributors do not know who benefits from their labor.

## acceptance test

A newcomer can find an artifact, apply it to a real use case, submit feedback or a request, see who can fulfill it, and inspect prior outcomes without replaying the community's chat history.
